# docs: 기획 문서 규칙

Slack 에이전트가 "개발 진행해"라는 요청을 받으면 코드를 쓰기 전에 이 폴더에 기획을 쓰고,
기획이 확정된 뒤에만 개발합니다. 이 규칙은 프로젝트에 `.piplup/plan-first` 파일이 있을 때만
적용됩니다 (Phase 28).

## 구조

```
docs/                 공통 (이 README, architecture.md: 영역이 공유하는 PEV·쓰기 게이트·저장소)
docs/linear/plan.md   Linear 에이전트의 기획
docs/code/plan.md     Code 에이전트의 기획
docs/notion/plan.md   Notion 에이전트의 기획
```

영역은 `linear`·`code`·`notion`입니다. 요청 메시지에 영역 이름(또는 `docs/<영역>`)이 있으면
그 영역으로 봅니다. 없으면 에이전트가 어느 영역인지 되묻습니다.

## 흐름

1. `linear 개발 진행해` → 에이전트가 `docs/linear/plan.md`를 씁니다 (`docs/` 아래만 쓸 수 있습니다).
   열린 질문마다 `추천:`이 붙습니다.
2. `기획 확정 linear` → 열린 질문이 있으면 **봇이 하나씩 묻습니다.** 질문과 추천이 나오면 답합니다:
   - `추천대로`: 추천을 결정으로 기록 (추천이 없는 질문에는 쓸 수 없음)
   - `결정: <내용>`: 직접 쓴 결정을 기록 (한 줄, 300자 이내)
   - `보류`: 이 질문은 열어 두고 다음으로
   - `나머지 추천대로`: 남은 질문을 추천대로 한 번에 기록 (개수를 알려 주고 실행, 추천 없는 질문이 있으면 거절)
   - `중단`: 검토를 끝냄 (기록한 결정은 남음)

   답마다 문서에 `- [x]`와 `결정:` 줄이 기록되고 스레드 브랜치에 커밋됩니다. 이 답들은 고정 명령이라
   문장 전체가 정확히 일치해야 합니다 ("추천대로 하자"는 답이 아닙니다). 검토는 30분 안에 이어 가야 하고,
   끊겨도 `기획 확정 linear`를 다시 보내면 문서에 남은 열린 질문부터 이어집니다.
3. 열린 질문이 모두 정해지면 봇이 알려 줍니다. **`기획 확정 linear`를 한 번 더 보내면** `상태: 확정`으로 바뀝니다.
   이 명령만 상태를 바꿀 수 있고, 에이전트가 직접 바꾸면 변경이 거부됩니다.
4. `linear 개발 진행해` → 이제 기획의 슬라이스를 한 번에 하나씩 구현합니다.

## 기획 문서를 쓰는 규칙

에이전트가 기획을 쓸 때 따르는 규칙(영역 폴더에 한 곳, 열린 질문마다 `추천:`, 구현된 것과 모순 금지 등)은
`harness/plan-docs.md`에 있고, 기획 단계 요청마다 프롬프트에 실립니다. 규칙을 바꾸려면 그 파일을 고치세요.

## 우회

작은 수정처럼 기획이 필요 없으면 요청 메시지에 명시하세요: `기획 없이`, `기획 우회`, `기획 건너뛰고`,
`docs 우회` 등. 그 **메시지 하나**에 한해 `docs/` 밖에도 쓸 수 있습니다. 다음 메시지부터는 다시
기획 단계가 적용됩니다. 우회해도 에이전트가 기획을 스스로 `확정`으로 바꿀 수는 없습니다.
"우회하지 마"처럼 부정이 붙은 표현은 우회로 보지 않습니다.

## `docs/<영역>/plan.md` 템플릿

```markdown
# <영역> 기획

상태: 초안

## 목표
## 범위 (이번에 할 것 / 하지 않을 것)
## 결정 사항
## 슬라이스
- [ ] 슬라이스 1: ...
## 열린 질문
- [ ] Q1. 사용자가 정해야 할 것
```

`상태:`는 `초안`과 `확정`만 씁니다. `## 열린 질문` 아래 `- [ ]`가 하나라도 남으면 확정할 수 없습니다.
