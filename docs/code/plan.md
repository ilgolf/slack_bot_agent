# Code 에이전트 기획: 스레드 작업을 PR로 올리기

상태: 확정

## 목표

편집 에이전트가 스레드 worktree(`bot/<스레드>` 브랜치)에서 일을 끝내면, 사용자가 Slack에서 한 마디로
그 브랜치를 푸시하고 PR을 만들 수 있게 한다. 지금은 PR을 올릴 방법이 없어 사용자가 직접 올려야 한다.

## 현재 상태 (읽어서 확인)

- 편집 에이전트는 파일 도구만 쓴다. 셸이 없고 `permission_mode="dontAsk"`라 `gh`·`git push`를 요청할 수 없다
  (`src/code/claude_sdk_runner.py` `edit_options`). 이 제한은 의도된 설계로 보이며 풀지 않는다.
- git은 `GitCommands`의 고정 하위 명령만 쓴다: `rev-parse status worktree branch add commit diff show`.
  모듈 머리 주석이 "The bot never pushes, merges, resets or checks out."이라고 못박는다 (`src/code/workspace.py`).
- 계획 검증은 "Git push"를 고위험 작업으로 거부한다 (`src/code/plan.py`).
- 사용자 고정 명령은 `실행`·`취소`·`폐기`·`기획 확정 <영역>`이다 (`src/code/workflow.py`). 쓰기는 사용자 명령으로만 일어난다.
- `gh`는 이 PC에 설치되어 있다. 푸시용 자격 증명과 `gh auth` 상태는 확인하지 못했다.

## 범위

이번에 할 것:
- 고정 명령 `PR`로 현재 스레드 브랜치를 푸시하고 PR을 만든다. 에이전트는 관여하지 않고 워크플로 코드가 실행한다.
- 결과로 PR URL을 답한다. 실패하면 이유를 답하고 재시도하지 않는다.

이번에 하지 않을 것:
- 에이전트에 `Bash`·`gh`를 여는 것, 임의 git/gh 인자를 받는 것.
- PR 병합·닫기·리뷰 요청·라벨. `main` 푸시, force push.
- 원본 체크아웃 변경.

## 결정 사항

- 푸시와 PR 생성은 **사용자 명령 뒤에 코드가** 한다. 에이전트 도구 목록은 바꾸지 않는다.
  (근거: 쓰기는 사용자 명령으로만, `src/code/workflow.py`; 편집 에이전트 무셸, `edit_options`)
- 실행하는 명령은 고정 문장이다: `git push` 한 형태와 `gh pr create` 한 형태. 브랜치는 `bot/` 접두사만,
  제목·본문은 코드가 만든다. 스레드나 에이전트가 쓴 문자열은 셸을 거치지 않는 argv 항목으로만 넘긴다.
  (근거: `GitCommands`의 셸 없는 고정 allowlist 방식)
- 미리보기의 커밋 수·변경 파일은 **로컬 기본 브랜치**를 기준으로 센다 (`git fetch`는 허용하지 않는다). 원격이 더 앞서 있으면 실제 PR과 다를 수 있으므로 미리보기에 그렇게 적는다. (사용자 결정, 2026-10-09)
- 요청자를 알 수 없으면(`user_id`가 없는 경로) `실행`은 항상 거절한다. (사용자 결정, 2026-10-09)
- 자동 재시도 없음. 푸시가 성공하고 PR 생성이 실패하면 "푸시는 됐고 PR만 실패"라고 정직하게 알린다.
