# 기획 문서 쓰는 규칙

`docs/<영역>/` 아래 기획·설계 문서를 쓸 때 지킵니다 (영역: `linear`·`code`·`notion`).

- **먼저 읽기**: 쓰기 전에 `docs/<영역>/`의 기존 문서와, 문서가 다루는 `src/`·`tests/`를 읽습니다. 같은 주제의 문서가 이미 있으면 새로 만들지 말고 그 파일을 고칩니다. 영역 문서는 `docs/<영역>/` 한 곳에만 둡니다 (`docs/` 루트에 같은 주제를 따로 만들지 않습니다).
- **형식**: 기획은 `docs/<영역>/plan.md`. 제목 바로 아래 줄에 `상태: 초안` 한 줄을 두고, 그다음에 목표 → 범위(이번에 할 것 / 하지 않을 것) → 결정 사항 → 슬라이스 → `## 열린 질문` 순서로 씁니다. 템플릿은 `docs/README.md`. 200줄 안쪽으로 씁니다.
- **열린 질문은 봇이 읽는 형식으로 씁니다.** `## 열린 질문` 아래에 `- [ ] Q3. 질문` 한 줄, 바로 아래 들여쓴 줄에 `추천: 답 (이유 한 줄)`. 사용자가 `기획 확정 <영역>`을 보내면 봇이 이 질문을 하나씩 묻고 사람의 답을 `- [x]`와 `결정:` 줄로 기록하므로, 형식이 다르면 읽히지 않습니다. 추천은 판단을 돕는 것이고 결정은 사용자 몫이라 질문을 체크하거나 `결정:` 줄을 쓰지 않습니다.
- **구현된 것과 모순되지 않게 씁니다.** 슬라이스는 실제 파일(`src/`·`tests/`)을 확인해 이미 구현된 것은 `- [x]`로 표시하고 근거 파일을 적습니다. 코드나 문서로 이미 답이 정해진 질문은 `- [x]`로 두고 근거를 적습니다. 결정 사항과 열린 질문이 서로 반대되는 말을 하지 않는지 마지막에 다시 읽습니다.
- **정직하게 씁니다.** 실행해 확인하지 못한 것은 확인했다고 쓰지 말고 "추측" 또는 "확인 못 함"으로 표시합니다. 사용자가 정해야 할 것을 대신 정하지 않습니다.
- **`상태:`는 바꾸지 않습니다.** `확정`은 사용자의 `기획 확정 <영역>` 명령만 만듭니다.
